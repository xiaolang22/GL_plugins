## 数据库设计
### ER图分析 

#### 实体
一共有4个**实体**：智能表格、工作表、模板工作表、人；以及一个非实体：操作日志 

- **智能表格**的属性包括：唯一id、表格名字、操作链接id 
- **工作表**的属性包括：唯一id、工作表名字、操作链接id、所属智能表格id、采用的模板工作表id 
- **模板工作表**的属性包括：唯一id、模板工作表名字、所属智能表格id、操作链接id 
- **人**的属性包括：唯一id、企业微信用户名称 
- **操作日志**的属性包括：唯一id、操作人、操作内容、操作时间、被操作对象id
#### 关系
- **智能表格与工作表**是一对多的关系，一个智能表格包含多个工作表，一个工作表属于唯一一个智能表格 ；
- **智能表格与模板工作表**是一对多的关系，一个智能表格包含多个模板工作表，一个模板工作表属于唯一一个智能表格； 
- **模板工作表与工作表**是一对多的关系，一个模板工作表可以产生多个工作表，一个工作表由唯一一个模板工作表产生 ；
- **人与智能表格/工作表/模板工作表**是多对多的关系，一个人可以对多个智能表格/工作表/模板工作表进行操作，一个智能表格/工作表/模板工作表可以被多个人操作

### 确定表格 
一共五个表格：智能表格、工作表、模板工作表、人、操作日志
### 1. 智能表格表 `docs`

```sql
CREATE TABLE docs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doc_id TEXT NOT NULL UNIQUE,     -- 企业微信文档ID
    doc_name TEXT NOT NULL,           -- 文档名称
    doc_url TEXT NOT NULL,            -- 文档链接
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by TEXT NOT NULL          -- 创建人userid
);
```

### 2. 模板工作表表 `templates`

```sql
CREATE TABLE templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doc_id TEXT NOT NULL,              -- 所属智能表格的doc_id（外键→docs）
    sheet_id TEXT NOT NULL UNIQUE,     -- 企业微信工作表ID
    sheet_name TEXT NOT NULL,          -- 模板名称，如 "订座信息表模板"
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by TEXT NOT NULL,
    FOREIGN KEY (doc_id) REFERENCES docs(doc_id) --外键约束，doc_id必须在docs表中存在
);
```

### 3. 工作表表 `sheets`

```sql
CREATE TABLE sheets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doc_id TEXT NOT NULL,              -- 所属智能表格doc_id（外键→docs）
    sheet_id TEXT NOT NULL UNIQUE,     -- 企业微信工作表ID
    sheet_name TEXT NOT NULL,          -- 如 "9-25晚市周五"
    sheet_date TEXT NOT NULL,          -- 工作表对应的日期
    session_type TEXT NOT NULL,        -- 'lunch' | 'dinner'
    weekday TEXT NOT NULL,             -- '周一' ~ '周日'，工作表对应的星期几
    template_id INTEGER NOT NULL,      -- 采用的模板id（外键→templates）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by TEXT NOT NULL,
    FOREIGN KEY (doc_id) REFERENCES docs(doc_id),
    FOREIGN KEY (template_id) REFERENCES templates(id)
);
```


### 4. 人员表 `users`

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    userid TEXT NOT NULL UNIQUE,       -- 企业微信userid
    name TEXT NOT NULL,                -- 用户名称
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 5. 操作日志表 `logs`

```sql
CREATE TABLE logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    operator_id INTEGER NOT NULL,      -- 操作人（外键→users）
    target_id INTEGER NOT NULL,        -- 被操作对象的id（指向对应表的id字段）
    operation_type TEXT NOT NULL,      -- 调用的插件工具，从实际注册的工具列表中选
    target_type TEXT NOT NULL,         -- 'doc' | 'sheet' | 'template'
    detail TEXT,                       -- 操作内容详情，解析用户指令+对比修改前后数据后生成的 JSON 对象
    error_msg TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (operator_id) REFERENCES users(id)
);
```


## 数据存储层设计
使用企业微信文档的智能表格作为数据存储层，智能表格名称为“订座信息表”
工作表分为普通工作表和模板工作表。
**普通工作表**：
- 以日期、早晚市、星期命名，例如：9-25晚市周五
- 每天包含两张工作表，分为早市和晚市
- 用于存储每天的订座信息
**模板工作表**：
- 名为“订座信息表模板”
- 包含预设好的工作表结构、内容和规则
- 用于给机器人提供创建普通工作表的模板
**与数据库的关系**：
- 普通工作表对应数据库的工作表表，模板工作表对应数据库的模板工作表表

## 代码架构
基于python + fast api实现
修改范围要求：
- 只允许修改`GL_plugins/booking_agent`目录下的文件
模块化要求：
- api原子操作实现放在一个py文件里面，包括直接实现企业微信文档的说明书中的原子api操作和获取access token等与api相关的原子操作
- 自定义复合操作放在一个py文件里面，包括按照模板新建工作表等复合操作
- main.py放各个工具的实现
文件结构：
```
GL_plugins/booking_agent/
├── db.py               # 数据库初始化与操作封装
├── api_wework.py       # 企业微信文档API原子操作
├── composite.py        # 复合业务操作（组合原子操作）
├── main.py             # FastAPI 路由与工具接口（含可调参数）
└── booking.db          # SQLite 数据库文件（自动生成）
```
参数配置要求：
- 所有可调参数需要放在main.py文件的最上面，便于程序员直接调整。可调参数包括CORP_ID、SECRET、工作表更新时间间隔等
