## booking agent 里的自动化功能整理

我按代码实际实现梳理了一下，自动化功能主要集中在 `main.py`、`composite.py` 和 `wecom_callback.py`。

---

## 1. 每日零点 buffer 自动管理

### 触发方式
- 在 `main.py:145-215` 启动了 APScheduler
- 每天北京时间 00:00:00 自动执行 buffer 管理
- 也支持手动触发 /test/trigger_buffer

### 代码入口
- _buffer_job_wrapper
- _start_scheduler
- /test/trigger_buffer

### 自动化行为
在 `composite.py:1827-2030` 里，buffer_manage_and_sync 依次做：

1. 更新 buffer 范围标记
   - 把属于 buffer 的工作表标记为 is_buffer = 1
   - 不是 buffer 范围的标记为 0

2. 删除过期离散工作表
   - 规则：sheet_date < 今天 且 is_buffer = 0
   - 这些表会被远端删除并同步本地数据库

3. 补足 buffer 范围内的新工作表
   - 从今天开始，按配置天数和场次补齐缺失 sheet
   - 若达到 255 张上限则跳过
   - 自动复制模板字段和记录

### 目的
- 维持“未来 + 过去一段时间”的工作表是常驻状态
- 避免表太多导致文档负担过重
- 保持订座表始终在可管理范围内

## 2. 企业微信回调自动同步

### 触发方式
- 通过企业微信服务端回调，把人工在前端修改的记录事件推回后端
- 入口在 `main.py:774-852`
- 回调验签和解密在 `wecom_callback.py:80-158`

### 自动化行为
在 `composite.py:2031-2315` 中：

#### 2.1 sync_remote_record_change
处理 update_record / add_record 回调

主要逻辑：
- 根据 sheet_id 定位本地工作表
- 拉取远端最新 records
- 对回调中涉及的 record_id 重新计算订座状态
- 如果 “是否已订” 和业务规则不一致，则自动修正
- 若某个 seat_name 被手动改重名，则自动标记为：
  “座位名称重复(原xxx)”

#### 2.2 sync_remote_record_delete
处理 delete_record 回调

主要逻辑：
- 根据 sheet_id 定位工作表
- 记录删除事件
- 写入日志，保持本地数据库和远端操作一致

### 目的
- 让本地 SQLite 和企业微信远端状态保持同步
- 即使用户在企业微信前端直接改了表，也能自动修正业务规则

## 3. 自动维护“是否已订”状态

这是最关键的业务自动化之一。

### 触发方式
- 新增记录时
- 更新记录时
- 回调同步时

### 逻辑
在 `composite.py:1060-1212` 里，订座相关字段是：

- 客人称呼
- 客人电话
- 人数
- 留菜
- 留位人

只要其中任一字段非空，就自动设为：

- 是否已订 = 已订座

如果全部为空，则自动设为：

- 是否已订 = 未订座

### 目的
- 避免人工忘记更新状态
- 保持订座状态与实际客人信息一致

---

## 4. 座位名称重复自动检测与修正

### 触发方式
- add_record 新增时
- 回调同步时

### 逻辑
- 新建记录时，如果当前工作表已存在同名 seat_name，直接报错拒绝
- 如果有人在企业微信前端手动造成重复命名，回调同步时会自动改成：
  “座位名称重复(原xxx)”

对应代码：
- `composite.py:1357-1367`
- `composite.py:2176-2207`

### 目的
- 防止座位名重复导致定位混乱
- 保证“按座位名查找记录”有稳定的唯一键

---

## 5. 自动生成模板填充数据

### 触发方式
- 创建模板工作表时
- 使用 _fill_sheet_from_template
- buffer 补表时也会复用模板

### 逻辑
在 `composite.py:297-381` 与 `composite.py:386-521` 中：

- 重命名默认字段
- 增加缺失字段
- 补充记录
- 设置分组规则
- 保持幂等，即重复执行不会重复创建脏数据

### 目的
- 统一所有表格结构
- 让新建的日期表与模板一致
- 方便批量创建和重试

## 6. 自动日志记录

### 触发方式

- 更新记录
- 添加记录
- 删除记录
- 查询记录
- buffer 管理
- 回调同步

### 代码位置
- `db.py:78-101`
- `composite.py:884-908`
- `composite.py:1240-1258`
- `composite.py:2219-2230`

### 目的
- 审计操作人
- 追踪变更
- 排查问题

---

## 7. 自动化功能总结一句话版

booking agent 里真正的自动化功能可以概括为 4 类：

1. 定时自动维护 buffer
   - 每日零点清理/补足表格

2. 自动同步微信端人工变更
   - 回调同步 add/update/delete

3. 自动维护业务状态
   - 是否已订、座位名重复等兜底修正

4. 自动落库与日志
   - 所有关键动作都写入 SQLite 和 logs
