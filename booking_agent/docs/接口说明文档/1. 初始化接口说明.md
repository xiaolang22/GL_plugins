## 初始化功能整理

从代码看，初始化阶段主要是 3 个关键能力，分别对应：
- /create_doc
- /create_template
- /create_bulk_sheets

---

## 1. /create_doc：创建智能表格文档
### 输入
- doc_name：文档名
- admin_users：可选，初始管理员列表
- operator_userid：操作者 userid
- operator_name：操作者名称
### 输出
- content：成功文本
- doc_id：文档 ID
- doc_url：文档访问链接
### 内部逻辑
调用 create_smart_sheet_and_sync，流程是：
1. 获取企业微信 access_token
2. 调用企业微信接口 create_doc 创建文档
3. 拿到 docid 和 url
4. 把文档写到 SQLite 的 docs 表
5. 把操作人写入 users 表
6. 写入 logs 记录
### 作用
这是“初始化的第一步”：先有一个总文档，后面再在里面创建模板和日常工作表。

---
## 2. /create_template：创建模板工作表

### 输入
- template_name：模板表名称
- operator_userid
- operator_name
### 输出
- content：成功提示
- sheet_id：模板工作表 ID
- template_db_id：数据库里的模板记录 ID
### 内部逻辑
调用 create_template_sheet_and_sync，流程是：
1. 读取数据库中第一个已存在的 doc_id
2. 在该文档中创建一张模板子表
3. 让默认字段改名为“座位名称”
4. 按顺序追加字段：
   - 座位名称
   - 座位容量
   - 座位备注
   - 客人称呼
   - 客人电话
   - 人数
   - 留菜
   - 留位人
   - 座位类型
   - 是否已订
5. 插入默认座位数据（房间、桌位列表）
6. 设置分组规则：按“是否已订”和“座位类型”分组
7. 把模板内容保存进 SQLite 的 templates 表，并写日志
### 作用
模板表是后续批量创建普通工作表的“蓝本”，保证每张表结构一致。

---
## 3. /create_bulk_sheets：批量创建未来日期工作表

### 输入
- operator_userid
- operator_name
- days：默认 90，表示从今天起创建未来多少天
- sessions：默认是 午市 + 晚市
- max_workers：并发填充时的线程数，默认 5
### 输出
返回统计结果，包含：
- total：总张数
- start_date / end_date
- phase1_failed_count
- phase2_success_count
- phase3_retry_success_count
- final_success_count
- final_failed_count
- phase1_failed
- phase3_retry_success
- phase3_retry_failed
### 内部逻辑
调用 create_bulk_sheets_and_sync，整个流程分三阶段：

1. 阶段一：串行创建子表
   - 根据日期和场次生成 sheet_name
   - 先按日期顺序创建子表
   - 保证工作表在企业微信文档中顺序正确

2. 阶段二：并发填充
   - 对已创建的子表并发调用 _fill_sheet_from_template
   - 补字段、加记录、设置分组
   - 这是为了加速

3. 阶段三：失败重试
   - 对阶段二失败的表串行重试
   - 由于 _fill_sheet_from_template 是幂等的，所以重试是安全的

4. 最后同步数据库
   - 把全部成功表插入 sheets 表
   - 写创建日志和汇总日志
### 作用
这是“批量初始化”的核心功能：按日历自动提前生成后续一段时间的订座表。

---

## 4. 初始化时序

整体顺序是：

1. 创建总文档 doc
2. 在 doc 下创建模板表 template
3. 根据模板在未来日期批量创建普通工作表

也就是：

Doc → Template → Many Sheets

这正是整个 booking agent 初始化逻辑的核心。
